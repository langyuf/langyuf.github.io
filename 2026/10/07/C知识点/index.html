C++知识点

1、C++常量

在 C++ 中定义常量主要有以下几种方式，推荐优先使用 const / constexpr，尽量少用 #define。

1. const：只读变量

  • 必须初始化，之后不能修改。
  • 类型安全，有作用域。
  • 不保证一定在编译期求值，可能是运行期初始化。

2. constexpr：编译期常量

可用于数组大小、模板参数、case 标签等编译期场景。
比 const 更强调“编译期常量”。
C++11 引入，C++14/17/20 不断增强。

3. inline constexpr：C++17 头文件共享常量

C++17 起可用。
适合在头文件中定义全局常量，多个翻译单元共享同一实体。
避免多重定义问题。

4 . enum / enum class：整型常量集合

  • enum 常用于定义整型常量。
  • enum class 是强类型枚举，更安全，推荐。

5. 类内静态常量

  • static constexpr 适合类内编译期常量。
  • C++17 起 static constexpr 数据成员隐式 inline，通常不需要类外定义。

6. #define：预处理宏，不推荐

  • 只是文本替换，没有类型检查、没有作用域。
  • 容易产生副作用和调试困难。
  • 现代 C++ 建议用 constexpr 替代。

7. C++20 constinit：保证静态初始化

  • 常用于避免静态初始化顺序问题。

选择建议

编译期常量：优先 constexpr
运行期只读变量：用 const
头文件共享常量：C++17 用 inline constexpr
整型常量集合：用 enum class
避免 #define 定义常量

5、C++11-智能指针

智能指针是 <memory> 头文件中的核心内容。它们是 C++11 引入的特性，用于自动管理动态分配的内存。智能指针的主要类型有：

  • std::unique_ptr：独占所有权的智能指针，同一时间只能有一个 unique_ptr 指向特定内存。
  • std::shared_ptr：共享所有权的智能指针，多个 shared_ptr 可以指向同一内存，内存在最后一个 shared_ptr 被销毁时释放。
  • std::weak_ptr：弱引用智能指针，用于与 shared_ptr 配合使用，避免循环引用导致的内存泄漏。

总结

  • unique_ptr 是独占所有权的智能指针，不能拷贝，只能移动。
  • 优先用 std::make_unique 创建。
  • 函数返回 unique_ptr 是安全的；传参一般用 const unique_ptr<T>& 或裸指针/引用。
  • 支持自定义删除器和数组。
  • 无状态删除器时，大小和性能几乎与裸指针相同。
  • 可以转为 shared_ptr，反之不行。
  • 多态基类必须有虚析构函数。
  • 默认首选 unique_ptr，需要共享所有权时再用 shared_ptr。

2、std::shared_ptr

关键点：

  • shared_ptr 可以拷贝，拷贝时引用计数增加。
  • 最后一个 shared_ptr 销毁时，对象自动 delete。
  • use_count() 返回当前共享该对象的 shared_ptr 数量。

创建方式 std::make_shared（推荐）

优点：

  • 一次内存分配：对象和控制块一起分配，效率高。
  • 异常安全：不会因为构造顺序导致泄漏。

引用计数原理

每个 shared_ptr 内部有两个指针：

  • 指向对象的指针。
  • 指向控制块的指针。

控制块里存：

  • 强引用计数（shared count）
  • 弱引用计数（weak count）
  • 删除器
  • 分配器

拷贝 shared_ptr 时，强引用计数原子递增；销毁时原子递减。减到 0 就销毁对象；弱引用计数也减到 0 时，控制块才释放。

线程安全性

  • 引用计数是线程安全的：多个线程拷贝/销毁指向同一对象的 shared_ptr，计数不会错。
  • 对象本身不是线程安全的：多个线程同时读写 *p 仍需加锁。
  • 同一个 shared_ptr 实例被多线程同时读写不是线程安全的：比如一个线程 p.reset()，另一个线程读 p，需要同步。

3、std::weak_ptr

它表示对某个由 std::shared_ptr 管理的对象的非拥有（non-owning）弱引用

shared_ptr 拥有对象，weak_ptr 只是“观察”对象，不延长对象生命周期；需要访问时用 lock() 临时提升成 shared_ptr。

核心特点

  • 不增加强引用计数，不影响对象销毁。
  • 不能直接 *w 或 w->，因为它不保证对象还存在。
  • 必须通过 w.lock() 得到 std::shared_ptr<T>：
    • 对象还在：返回有效 shared_ptr
    • 对象已销毁：返回空 shared_ptr
  • 当最后一个 shared_ptr 销毁时，对象销毁；weak_ptr 仍然可以存在，但 expired() == true。
  • weak_ptr 会延长控制块的生命，但不会延长被管理对象的生命。
